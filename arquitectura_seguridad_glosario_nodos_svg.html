Cabecera del SVG y convenciones

En el diagrama original, el color rosa y borde discontinuo marcan componentes opcionales (capa 7A mesh, OpenTelemetry ampliado, banda Mermaid). El resto forma el baseline ISO 27001 / SGSI, RGPD operativo y prácticas DevSecOps descritas en el HTML principal.

Título: «Arquitectura de seguridad cloud»

Visión de controles de seguridad en la nube (Azure en este despliegue) desde el borde hasta datos, claves y pipeline.

Subtítulo de stack

Express (Node)
Node.js es el runtime JavaScript del servidor. Express es el framework web minimalista sobre el que corre la API.
SQL Server
Base de datos relacional Microsoft; aquí como almacén principal de negocio.
Azure
Nube Microsoft donde viven Front Door, Entra ID, Key Vault, etc.
borde
Perímetro de entrada (CDN, WAF, gateway) antes de la aplicación.
GraphQL
API de consulta sobre HTTP con esquema tipado; en el diagrama va federada (varios servicios bajo un único gateway).
identidad / app / datos / claves
Capas lógicas: quién eres (IdP), lógica de negocio, persistencia, y gestión criptográfica centralizada.
mesh/eventos
Comunicación entre microservicios (service mesh opcional) y mensajería asíncrona (Kafka/Event Hubs).
observabilidad / DevSecOps
Logs, métricas, trazas y seguridad integrada en CI/CD (tests, SAST, SBOM, despliegue).

Capa 1 — EDGE / ENTRYPOINT

Subtítulo del panel: Azure Front Door + WAF + API Management + OSS. WAF = Web Application Firewall. APIM = API Management (gateway de APIs). OSS = open source en paralelo (p. ej. Kong como alternativa a APIM).

Usuarios

Browser / mobile
Clientes humanos: navegador web o aplicación nativa/híbrida.
REST / GraphQL / WS
REST: HTTP con recursos y verbos. GraphQL: consultas tipadas a un endpoint. WS = WebSocket: canal bidireccional persistente para tiempo real.

APIs externas

Partners / B2B
Integración negocio a negocio con terceros (no usuario final ocasional).
Webhooks / OAuth2
Webhook: callback HTTP cuando ocurre un evento. OAuth 2.0: marco de autorización (tokens, clientes); suele ir con OIDC para identidad.

Azure Front Door

CDN Global
CDN (Content Delivery Network): red de puntos de presencia que cachea y sirve contenido cerca del usuario.
Geo-routing
Enrutar tráfico según geografía (latencia, soberanía o reglas de negocio).
Anycast BGP
BGP (Border Gateway Protocol): enrutamiento entre sistemas autónomos. Anycast: misma IP anunciada en varios sitios; el tráfico va al PoP «más cercano».
DDoS L3/L4 prot.
DDoS: denegación de servicio distribuida. L3/L4: capas OSI red/transporte (volumen, SYN flood, etc.), frente a L7 que es aplicación.
PoP caching
PoP (Point of Presence): edge donde se cachea contenido estático o respuestas acelerables.
Health probes
Comprobaciones periódicas a los orígenes para saber si están sanos.
Origin failover
Si un origen falla, conmutar a réplica u otro backend sin intervención manual.

Azure WAF

OWASP CRS 3.2
OWASP: Open Web Application Security Project. CRS: Core Rule Set, conjunto de reglas contra ataques web comunes (versión 3.2).
SQLi / XSS / CSRF
SQLi: inyección SQL. XSS: Cross-Site Scripting (inyección de script en páginas). CSRF: Cross-Site Request Forgery (forzar acciones en sesión ajena).
LFI / RFI / SSRF
LFI/RFI: inclusión local/remota de ficheros. SSRF: Server-Side Request Forgery (el servidor es engañado para llamar a redes internas).
Bot fingerprinting
Detectar automatización maliciosa por huellas TLS, cabeceras, comportamiento.
Geo-blocking
Bloquear o permitir países/regiones por IP.
IP reputation feed
Listas de IPs maliciosas conocidas (feeds) para bloqueo o puntuación.
Custom rule sets
Reglas propias además del CRS (URLs, cabeceras, rate por ruta, etc.).

TLS Termination

TLS
Transport Layer Security: cifrado y autenticación del canal HTTP. Termination: el TLS se descifra en el edge/balanceador y hacia dentro puede ir HTTP cifrado de nuevo o no, según diseño.
TLS 1.2 / 1.3 only
Versiones modernas; se excluyen protocolos obsoletos (SSL, TLS 1.0/1.1).
ECDHE key exchange
Intercambio efímero de claves con curvas elípticas; ofrece forward secrecy (comprometer la clave larga no revela sesiones pasadas).
AES-256-GCM
Cifrado simétrico robusto en modo GCM (AEAD: autenticación + confidencialidad).
HSTS preload
HTTP Strict Transport Security: el navegador solo usa HTTPS durante un tiempo; «preload» entra en listas de navegadores.
OCSP stapling
El servidor adjunta estado de revocación del certificado en el handshake, acelerando validación.
Cert pinning
Asociar explícitamente una app a la huella de un certificado/CA esperada (reduce riesgo de CA comprometida).
mTLS for B2B
mTLS (mutual TLS): cliente y servidor presentan certificado; típico en integraciones B2B.

Azure APIM / Kong

API Gateway
Punto único de entrada a APIs: enrutado, políticas, cuotas, transformación.
API key validation
Comprueba claves de API en cabecera o query para clientes programáticos.
OAuth2 scopes
Scope: permiso granular dentro de un token OAuth (qué puede hacer el cliente).
JWT pre-validation
JWT (JSON Web Token): token firmado. Validar firma, audiencia y expiración en el gateway antes de llegar al backend.
Versioning / routing
Enrutar /v1 vs /v2 o cabeceras de versión hacia distintos backends.
Request transform
Modificar cabeceras, cuerpo o query en tránsito (normalización, inyección de correlación).
Schema validation
Comprobar JSON/XML contra esquema (OpenAPI, JSON Schema) en el borde.

Rate Limiting

Redis cluster
Redis: almacén clave-valor en memoria, aquí como contador distribuido para límites por IP/usuario.
Token bucket algo
Algoritmo clásico: «cubeta» de tokens que se repone a ritmo constante; cada petición consume tokens; evita ráfagas mayores al cupo.
Per IP / per user / per endpoint
Granularidad del límite: abuso por origen, por cuenta o por ruta crítica.
429 + Retry-After
429: código HTTP «Too Many Requests». Retry-After: cabecera que indica cuándo reintentar.
IP allowlist/blocklist
Listas explícitas de permitir o denegar direcciones IP.
Circuit breaker
Patrón que deja de llamar a un servicio degradado para no empeorar la cascada; tras tiempo «half-open» prueba de nuevo.

Secuencia Edge (panel lateral)

① … ⑥
Orden lógico: Front Door → WAF → TLS → APIM → rate limit → tráfico hacia GraphQL/APIs internas con trazas correlacionadas.
AEAD
Authenticated Encryption with Associated Data (cifrado que garantiza integridad).
Key Vault
Azure Key Vault: almacén de secretos y claves (capa 6 del diagrama).
Norte-sur
Tráfico usuario↔datacenter (vs este-oeste entre servicios internos).

Capa 2 — GRAPHQL FEDERATION

Subtítulo: Apollo Federation v2 — varios subgraphs (servicios GraphQL) se unen en un supergraph único. El masking en resolvers alinea la salida con la capa 4 (API) y RGPD.

Anti-exfiltración: evitar que un atacante extraiga masivamente datos vía GraphQL (profundidad, coste, consultas acotadas, cuotas de export).

GraphQL Gateway

Apollo Router (Rust)
Implementación oficial de gateway en Rust para supergraphs federados; baja latencia y seguridad endurecida.
Query planning
El router calcula qué subgraphs invocar y en qué orden para satisfacer una query.
Schema composition
Unir esquemas parciales en un supergraph coherente (directivas @key, @external, etc.).
Persisted queries
Solo se aceptan hashes/IDs de queries pre-registradas (APQ); reduce superficie de ataques ad hoc.
Query depth limiting
Límite a la profundidad de anidación de campos para evitar queries «árbol» costosas.
Cost analysis
Asignar «coste» a campos y rechazar queries que superen presupuesto (anti-abuso).
Response caching
Cachear respuestas idempotentes en edge o gateway con clave de query+variables+usuario.
Mask PII en resolvers
PII (Personally Identifiable Information): enmascarar DNI, email, teléfono en la respuesta según rol.

Auth subgraph

login / refresh / logout
Mutaciones o flujos que delegan en el IdP (capa 3) para sesión y tokens.
MFA challenge · session types
Desafío de segundo factor y distinción de sesiones (p. ej. larga vs elevada).

User subgraph

User / Profile types
Tipos GraphQL de usuario y perfil expuestos solo con campos permitidos.
Roles / permissions
Autorización a nivel de tipos/campos o datos enlazados al rol del token.
Preferences
Preferencias de usuario no sensibles o filtradas según política.

Data subgraph

Entities + federated queries
Entidades con @key que otros subgraphs extienden; queries que el router reparte entre servicios.

Panel lateral Federación

IdP
Identity Provider (proveedor de identidad), p. ej. Entra ID.
RLS
Row-Level Security: filtrado de filas por tenant/usuario en base de datos.
OPA
Open Policy Agent (políticas declarativas en Rego); aquí en autorización fina junto a RLS.
Introspección / errores opacos
En producción suele deshabilitarse la introspección pública del esquema; errores sin detalles internos.

Capa 3 — IDENTITY / MFA

Subtítulo: Azure Entra ID + OPA + SPIFFE + Redis sessions. SPIFFE (Secure Production Identity Framework For Everyone) estandariza identidades de carga de trabajo (SVID); en el diagrama conecta con mTLS y capa 6. OPA ya detallado en ABAC.

Azure Entra ID

Servicio de identidad Microsoft (antes Azure AD): usuarios, grupos, aplicaciones, tokens y políticas.

OIDC / SAML2 / WS-Fed
OIDC (OpenID Connect): capa de identidad sobre OAuth 2.0 (tokens id_token). SAML 2.0: XML firmado para SSO empresarial. WS-Federation: protocolo Microsoft/heredado para federación con ADFS y similares.
Authorization code + PKCE
Flujo OAuth para apps públicas: el navegador recibe un «code» canjeable por tokens; PKCE (Proof Key for Code Exchange, RFC 7636) evita robo del code sin el verificador criptográfico inicial.
Device code flow
Para dispositivos sin teclado/browser cómodo: muestra un código al usuario para autorizar en otro dispositivo.
Client credentials
Flujo OAuth máquina-a-máquina: el cliente se autentica con secreto o certificado y obtiene token sin usuario humano.
Conditional Access
Políticas «si condición entonces exigir acción»: MFA, dispositivo híbrido Azure AD, ubicación, riesgo, aplicación aprobada, etc.
PIM privileged roles
PIM (Privileged Identity Management): roles administrativos a tiempo limitado con aprobación y auditoría (just-in-time admin).
Identity protection
Detección de riesgos (credenciales filtradas, ubicaciones imposibles, TOR) y respuestas automáticas o MFA escalonado.

MFA

MFA
Multi-Factor Authentication: algo que sabes + algo que tienes + algo que eres.
TOTP / FIDO2 / WebAuthn
TOTP (Time-based One-Time Password, RFC 6238): códigos de app autenticadora. FIDO2 / WebAuthn: estándar W3C/FIDO para claves criptográficas en hardware o plataforma (passkeys).
Passkeys (resident key)
Credencial WebAuthn almacenada en el autenticador (residente), login sin contraseña tradicional.
SMS OTP (fallback)
Contraseña de un solo uso por SMS: más débil (SIM swap); solo como excepción auditada.
Recovery codes
Códigos de un solo uso para recuperar acceso si se pierde el segundo factor.

JWT tokens

JWT
JSON Web Token: tres segmentos Base64 (cabecera, payload, firma); no cifra el payload por defecto.
RS256 / ES256
Algoritmos de firma: RSA (clave asimétrica) o ECDSA con curvas elípticas (ES256).
Access / Refresh
Access corto (p. ej. 15 min) para APIs; refresh largo (p. ej. 7 d) solo para obtener nuevos access con rotación.
Claims: sub, iat, jti
sub: sujeto (usuario). iat: issued at. jti: ID único del token para revocación en lista.
JWKS endpoint
JSON Web Key Set: publica claves públicas para verificar firmas sin compartir la privada.
JTI revocation list
Conjunto de tokens revocados por su jti hasta expirar.
Token introspection
RFC 7662: endpoint que indica si un token sigue activo (útil para opaque tokens o validación central).

RBAC

RBAC
Role-Based Access Control: permisos agrupados en roles asignados a usuarios o servicios.
service-account roles
Identidades no humanas (client credentials) con roles mínimos.
Least privilege / JIT / inheritance
Mínimo privilegio necesario; JIT (just-in-time) eleva temporalmente; herencia evita duplicar permisos.

ABAC / OPA

ABAC
Attribute-Based Access Control: decisiones por atributos (tenant, sensibilidad del dato, horario, riesgo).
Rego
Lenguaje declarativo de políticas de OPA.
Data-aware policies
Políticas que consultan datos de contexto o microservicios antes de permitir.
Bundle OCI
Distribución versionada de bundles de políticas como artefacto OCI (Open Container Initiative).

Redis sessions

Session TTL / sliding
TTL (time to live): caducidad de sesión; «sliding» renueva al actividad.
TLS in-transit / Encrypted at rest
Cifrado en red hacia Redis y cifrado de volúmenes/disco.
ACL per command
Redis 6+: listas de control de acceso por usuario de Redis y comandos permitidos.

Cadena IdP → sesión (panel lateral)

SVC accounts
Cuentas de servicio para workloads automatizados.
HSM
Hardware Security Module: módulo físico o cloud para claves no exportables (capa 6).

Capa 4 — APPLICATION LAYER

Node.js + Express + Apollo/GraphQL; ORM Object-Relational Mapping (Sequelize/Prisma). CORS Cross-Origin Resource Sharing; CSP Content Security Policy.

API Server

Node.js v20 LTS
Versión con soporte a largo plazo (Long-Term Support).
Helmet
Middleware que ajusta cabeceras HTTP de seguridad (CSP base, HSTS opcional, etc.).
express-rate-limit · Redis store
Límite de peticiones por IP/usuario persistido en Redis (coherente en varias réplicas).
Cluster PM2
PM2: process manager; cluster: varios workers Node en un host para usar todos los cores.
graceful shutdown
Al recibir SIGTERM, dejar de aceptar conexiones nuevas y terminar peticiones en curso antes de salir.

Auth middleware

iat / exp / nbf
Claims de tiempo: emitido, expira, no antes de (validación temporal).
Context injection
Rellenar req.user, tenant, roles para capas inferiores.

Validation

Zod / Joi
Librerías de esquema TypeScript-first (Zod) o clásica (Joi) para validar entrada.
Out: mask PII (rol)
Salida filtrada según rol antes de serializar JSON/GraphQL.

Business logic

CQRS
Command Query Responsibility Segregation: separar modelos de lectura y escritura.
DTO
Data Transfer Object: objeto de capa de aplicación sin exponer entidad de persistencia.
Saga orchestration
Orquestación de transacciones largas con compensación entre servicios.

ORM layer

Parameterized queries
Consultas con placeholders; mitiga inyección SQL al no concatenar SQL con entrada.
Multi-tenancy filter
Filtro automático por tenant_id en cada query.

Franja Data masking

DDM
Dynamic Data Masking en SQL Server: oculta dígitos de columnas según rol de base de datos.
Always Encrypted
Cifrado de columna donde el motor no ve texto claro; claves en Key Vault/HSM.

Capa 5 — DATA SECURITY / RGPD

SQL Server

Always Encrypted cols
Columnas cifradas de extremo a extremo con CMK/CEK (ver capa 6).
Row-level security
Políticas T-SQL que filtran filas por usuario de sesión.
SQL Server Audit
Registro de accesos y DML/DDL a destino (archivo, aplicación externa).
Defender for SQL
Capa de detección de amenazas de Microsoft Defender para bases SQL.
Always On / DR
Alta disponibilidad con grupos de disponibilidad; DR disaster recovery según RTO/RPO.
VNet / Express · Encrypt
Conectividad privada (Azure VNet, ExpressRoute) y cifrado de conexión (TLS/TDS encrypt).

TDE encryption

TDE
Transparent Data Encryption: cifra archivos de datos y log en reposo con una DEK protegida por KEK.
DEK + KEK
Data Encryption Key (en BD) cifrada por Key Encryption Key (en Key Vault/HSM).
CMK
Customer-Managed Key: el cliente controla la KEK en su Key Vault.
FIPS 140-2 L3
Nivel de validación criptográfica federal (EE.UU.); L3 implica detección de manipulación física/lógica.

Field encrypt + app

AES-GCM
Cifrado simétrico autenticado a nivel aplicación para campos sensibles.
Per-tenant DEK
Clave de datos por inquilino para aislamiento criptográfico.
Deterministic / Randomized
Deterministic AE permite igualdad/búsqueda exacta cifrada; randomized es más seguro para lecturas puntuales.
HMAC
Hash Message Authentication Code: integridad/autenticación de mensaje con clave secreta.
Tokenization PAN
Sustituir número de tarjeta (PAN) por token sin valor fuera del vault de tokenización.

PII / RGPD

RGPD
Reglamento (UE) 2016/679 de protección de datos personales.
Right to erasure
Derecho al olvido: mecanismo para borrar o anonimizar datos del interesado.
DPA
Data Processing Agreement: contrato con encargados del tratamiento (Art. 28 RGPD).

Backups cifrados

PITR / LTR
Point-in-time restore (ventana corta, p. ej. 35 d). Long-term retention años para compliance.
WORM
Write Once Read Many / inmutabilidad: backups no modificables hasta expiración.
RTO / RPO
Recovery Time Objective: tiempo máximo de caída. Recovery Point Objective: pérdida máxima de datos aceptable.

Capa 6 — KEY MANAGEMENT (hub crítico)

Azure Key Vault

Secrets / Keys / Certs
Tres tipos de objeto: cadenas secretas, claves criptográficas, certificados X.509.
Soft delete + purge protect
Borrado recuperable y protección contra purga definitiva accidental o maliciosa.
Private link VNet
Acceso al vault por IP privada dentro de la red virtual sin exponerlo a Internet.

Managed HSM

RSA-4096 / EC P-384
Tamaños de clave asimétrica; P-384 es curva NIST secp384r1.
m-of-n quorum
Se requieren m administradores de n totales para operaciones críticas (ceremonias de clave).

Key rotation

Zero-downtime rotate
Superposición de versiones de clave (kid) para que verificadores acepten ambas durante la transición.

TLS / mTLS certs

CA
Certificate Authority: emisor de certificados.
SPIFFE SVID
SPIFFE Verifiable Identity Document: certificado corto que identifica el workload.
ACM
AWS Certificate Manager (referencia multi-nube) o gestión automática de renovación en cloud.
CRL / OCSP
Lista de revocación o estado en línea de certificados.
SAN
Subject Alternative Name: nombres adicionales en el certificado (servicios individuales).

JWT signing keys / App secrets

Managed identity pull
La carga de trabajo obtiene token de Azure sin credencial en código y lee secretos del vault.
Secret scanning CI
Herramientas (gitleaks, etc.) que fallan el pipeline si detectan secretos en el repo.

Capa 7A — SERVICE-TO-SERVICE (mTLS) Opcional

Istio mesh

Istio
Service mesh para Kubernetes: políticas, observabilidad y mTLS entre pods.
Envoy sidecar
Proxy de datos colocado junto a cada pod; intercepta todo el tráfico saliente/entrante.
Canary releases
Despliegue gradual: un pequeño % de tráfico a la nueva versión.

mTLS / OPA authz

Workload identity
Identidad de pod/servicio en la nube (Azure AD workload ID, IRSA en AWS, etc.).
Admission webhook
Webhook de admisión en Kubernetes que valida manifiestos contra políticas OPA/Gatekeeper.

Capa 7B — EVENT SECURITY

Kafka / Event Hubs

SASL/SCRAM-SHA-512
SASL: capa de autenticación. SCRAM: mecanismo resistente a replay con hash iterado (SHA-512).
Topic ACL / IAM
Control de quién produce/consume en qué topic; en cloud suele integrarse con IAM del proveedor.
Schema Registry
Repositorio de esquemas Avro/Protobuf/JSON Schema versionados para contratos de eventos.
Exactly-once semantics
Garantías de entrega sin duplicados ni pérdidas (combinando idempotencia, transacciones y offsets).

Message signing / DLQ

HMAC-SHA256
Firma simétrica del mensaje para integridad y autenticación entre productores/consumidores de confianza.
DLQ
Dead Letter Queue: cola de mensajes que fallaron tras reintentos, para inspección sin bloquear el flujo principal.

Capa 8A — OBSERVABILIDAD / AUDIT

OpenTelemetry Opcional

OTel
Estándar unificado de trazas, métricas y logs con SDKs y exportadores vendor-neutral.
Sampling policy
Reducir volumen de trazas (p. ej. 1% de peticiones) manteniendo representatividad.

Logs centralizados

ELK
Elasticsearch + Logstash + Kibana; stack de búsqueda y visualización de logs.

MS Sentinel SIEM

SIEM
Security Information and Event Management: correlación de eventos de seguridad.
SOAR
Security Orchestration, Automation and Response: playbooks automáticos ante incidentes.
KQL
Kusto Query Language: lenguaje de consulta de Log Analytics / Sentinel.
MITRE ATT&CK
Marco de tácticas y técnicas de adversarios; mapear detecciones a TTPs.
SOC
Security Operations Center: equipo que responde a alertas.

Audit logs inmutables

WORM blob storage
Almacenamiento de objetos con política de inmutabilidad legal/compliance.
Cryptographic chaining
Cada entrada incluye hash de la anterior (cadena) para detectar alteraciones.

Lint & estático / Tests / E2E / Smoke

ESLint / Stylelint / Prettier

GHA / ADO

Jest / Vitest / Playwright / Cypress

Testcontainers

Pact

K8s readiness

SAST + calidad

SAST
Static Application Security Testing: análisis de código fuente sin ejecutarlo.
CodeQL / SARIF

Semgrep
Motor de reglas ligero para patrones inseguros multi-lenguaje.
Taint analysis

SCA / dependencias

SCA

CVE / NVD

Trivy
Escáner de imágenes OCI y repos en busca de CVE.

DAST · SBOM · build · despliegue

DAST
Dynamic Application Security Testing: pruebas contra la app en ejecución (ZAP).
OWASP ZAP
Proxy y escáner DAST de código abierto.
IAST
Interactive AST: agente en runtime que combina cobertura y análisis.
CycloneDX / SPDX
Formatos estándar de SBOM (Software Bill of Materials).
cosign / Sigstore
Firma y verificación de imágenes OCI y artefactos con claves cortas o OIDC.
SLSA
Supply-chain Levels for Software Artifacts: marco de integridad de cadena de suministro (provenance).

Hub de material criptográfico (callout Key Vault)

Resume cómo Key Vault/HSM alimenta SQL (TDE, EKM, Always Encrypted), cadenas de conexión, APIM, firmas JWT, certificados mTLS/SPIFFE y CI/CD vía OIDC.

EKM
Extensible Key Management: SQL Server usa módulo externo (Key Vault) para TDE/backup keys.

Banda «REFERENCIA MERMAID (ELK)» — controles opcionales Opcional

Diagramas Mermaid/ELK del cliente condensados en tarjetas; términos adicionales:

Edge · contrato · contexto

Swagger / Stoplight / Redoc
Herramientas de documentación OpenAPI interactiva.
RCO
Request Context Object: objeto con userId, deviceId, riskScore, atributos ABAC propagados en la petición.

IdP · PDP · riesgo

PDP
Policy Decision Point: motor que devuelve ALLOW/DENY (p. ej. Zero Trust centralizado).
Identity risk scoring
Puntuación de riesgo por señales de IdP o ML (anomalías, credenciales filtradas) que refuerza Conditional Access.

App · frontera dura

Sanitizer
