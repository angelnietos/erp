# Plan: Keycloak OIDC Auth Library (Futuro Microservicio)

## Resumen

Implementar autenticación con Keycloak OIDC integrado en el ecosistema Angular/NestJS actual, con arquitectura preparada para ser un microservicio independiente en el futuro.

## Arquitectura Objetivo

```
Angular (josanz-web-app, saas-platform)
   ↓ (OIDC/OAuth2)
Keycloak (realm por cliente)
   ↓ (tokens)
Login theme personalizado
   ↓
OIDC tokens (JWT)
   ↓
NestJS API (middleware de validación)
   ↓
Validación JWT + roles + tenant
```

## Flujo Actual (Reconnaissanse)

- **Frontend**: `AuthService` en `libs/browser/data-access/identity/data-access/src/lib/services/auth.service.ts` - llama a `/api/auth/login` con email/password
- **Backend**: `AuthService` en `libs/node/backend/identity/backend/src/lib/application/services/auth.service.ts` - valida credenciales contra Prisma, genera JWT propio
- **JWT Strategy**: `libs/node/backend/identity/backend/src/lib/infrastructure/auth/jwt.strategy.ts` - valida JWT con secreto local

## Cambios en Backend (apps/backend)

### 1. Docker Compose - Keycloak service

**Archivo**: `docker-compose.yml` (añadir)

```yaml
services:
  keycloak-db:
    image: postgres:16
    environment:
      POSTGRES_DB: keycloak
      POSTGRES_USER: keycloak
      POSTGRES_PASSWORD: keycloak
    volumes:
      - keycloak_data:/var/lib/postgresql/data
    networks:
      - keycloak-network

  keycloak:
    image: quay.io/keycloak/keycloak:24.0.2
    environment:
      KEYCLOAK_ADMIN: admin
      KEYCLOAK_ADMIN_PASSWORD: admin
      KC_DB: postgres
      KC_DB_URL_HOST: keycloak-db
      KC_DB_USERNAME: keycloak
      KC_DB_PASSWORD: keycloak
      KC_DB_DATABASE: keycloak
      KC_HOSTNAME: localhost
      KC_HOSTNAME_STRICT: "false"
      KC_PROXY: edge
      KEYCLOAK_FRONTEND_URL: http://localhost:8080
    command: start-dev --import-realm
    volumes:
      - ./docker/keycloak/realms:/opt/keycloak/data/import
      - ./docker/keycloak/themes:/opt/keycloak/themes
    ports:
      - "8080:8080"
    depends_on:
      - keycloak-db
    networks:
      - keycloak-network

volumes:
  keycloak_data:

networks:
  keycloak-network:
    driver: bridge
```

## Notas Futuras (Microservicio)

La librería `auth-keycloak` está diseñada para migrar fácilmente a un microservicio porque:

1. Los puertos (ports) están en `identity-core` (isomorphic)
2. La lógica de validación está aislada en `auth-keycloak`
3. El módulo es autocontenible con `forRoot()`
4. Los controllers pueden exportarse a un nuevo `apps/auth-service`

## Consideraciones Técnicas

### Estrategia Dual (Compatibilidad)
El backend detectará automáticamente el tipo de token:
- **Token Keycloak**: Contendrá `iss: https://keycloak/auth/realms/...`
- **Token JWT local**: Usará el secreto JWT_SECRET existente

### Claims Requeridos
Los tokens Keycloak deben incluir claims personalizados:
- `tenant_id` (UUID del tenant cliente)
- `client_roles` (roles específicos del cliente app)

Esto se configura en Keycloak con **Mappers** en el Client Scope.
